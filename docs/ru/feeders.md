# Фидеры
{: #feeders }

Фидер представляет собой приёмник, обычно Raspberry Pi с антенной, который отправляет принятые сигналы воздушных судов в airplanes.live. Вкладка **Фидер** следит за вашими фидерами и предупреждает, когда какой-то из них отключается. Как настроить фидер, описано в [руководстве по настройке airplanes.live](https://airplanes.live/get-started/).

Добавление фидера здесь и его [привязка](/ru/getting-started#link-feeder) для Pro являются отдельными шагами. Можно сделать одно без другого.

## Как узнать ID фидера
{: #feeder-id }

У каждого фидера есть ID, UUID вида `3f2c8a1e-9b7d-4e2a-8c1f-5d6e7a8b9c0d`. На фидере, настроенном скриптом airplanes.live для передачи данных, его можно вывести командой:

```
cat /usr/local/share/airplanes/airplanes-uuid
```

В образе фидера airplanes.live это файл `/boot/airplanes-uuid`.

## Добавление фидера
{: #add }

<a class="guide-shot" href="/assets/images/feeders/add-feeder.webp"><img src="/assets/images/feeders/add-feeder.webp" width="540" height="1200" loading="lazy" alt="Экран добавления фидера с полями ID, метки, IP-адреса и местоположения"></a>

Нажмите кнопку **+** на вкладке «Фидер». Заполнить **Новый фидер** можно тремя способами:

- **Обнаружить Локальный Фидер**: находит фидеры в той же сети, что и телефон, и заполняет поля. Если найдено несколько, выберите один.
- **Сканировать QR-код**: сканирует QR-код фидера, созданный приложением на другом устройстве, см. [Поделиться фидером](#share).
- Ввести **ID фидера** вручную.

Необязательные поля:

- **Метка**: название фидера. Если его нет, приложение использует MLAT-имя фидера из airplanes.live или последние пять символов его ID.
- **IP-адрес**: адрес, по которому для этого фидера работает tar1090 или graphs1090, например `192.168.0.42`. Тогда приложение покажет кнопки для их открытия.
- **Позиция**: широта и долгота, например `50.8006, 6.0619`.

## Список фидеров
{: #list }

Заголовок показывает, все ли фидеры в сети. Для каждого фидера показаны статус, частота сообщений Beast (сообщ./с), скорость передачи данных (Кбит/с) и статистика MLAT с долей выбросов и числом пиров. Список можно отсортировать по **Метке** или **Частоте сообщений**.

Когда сервер приложения отслеживает ваши фидеры, статус приходит с сервера, например «Ожидание первой проверки», «Не в сети с …» или «Возможен сбой airplanes.live». Проблемы, найденные сервером, показаны ниже, например «нет клиента MLAT». В бесплатной версии отслеживается меньше фидеров, чем с привязанным фидером. Фидеры сверх этого показывают «Не отслеживается, достигнут лимит фидеров» и кнопку **Повысить лимит**, чтобы [привязать свой фидер](/ru/getting-started#link-feeder).

Нажмите на фидер, чтобы увидеть больше:

- **Показать фид на карте**: открывает в браузере globe.airplanes.live с тем, что принимает этот фидер.
- **Переименовать** и **Установить IP-адрес**.
- **TAR1090** и **GRAPHS1090**: открывают собственные веб-страницы фидера. Они появляются, когда задан IP-адрес.
- **Мониторинг**: статус и проблемы этого фидера по данным сервера, а также проверки, для которых ещё недостаточно данных. Показывается, только когда сервер отслеживает ваши фидеры.
- **Статистика**: графики частоты сообщений и выбросов MLAT за 30 дней. Когда сервер отслеживает ваши фидеры, графики показывают частоту сообщений, пиры MLAT и выбросы MLAT из почасовой истории сервера.
- **Создать QR-код**, см. ниже.
- **Уведомлять, когда offline**, см. ниже.
- **Удалить фидер**.

## Уведомления об отключении
{: #offline }

**Уведомлять, когда offline** задаёт, сколько фидер может быть не в сети, прежде чем вы получите уведомление: **Выкл.**, 6, 12, 24 или 48 часов. У новых фидеров стоит 48 часов. На Android 13 и новее при включении приложение запрашивает разрешение на уведомления.

Если сервер приложения это поддерживает, он отслеживает ваши фидеры, даже когда приложение закрыто. Фидер считается отключённым, если у него не было соединения с airplanes.live в течение выбранного времени и это подтвердили как минимум две проверки. Сервер не считает фидеры отключёнными, пока у самого airplanes.live проблемы или много фидеров пропадает одновременно. Тогда вы получаете «Фидер не в сети», а когда он вернётся, «Фидер снова в сети».

Сервер также ищет проблемы и присылает «Проблемы фидера», когда находит одну из них:

- нет клиента MLAT
- нет пиров MLAT
- ошибки синхронизации MLAT
- много выбросов MLAT
- принимает намного меньше сообщений, чем обычно
- постоянно переподключается
- ID фидера используется несколькими фидерами

Отключить их можно в **Настройки** › **Фидер** › **Оповещения о проблемах**.

Уведомления сервера приходят вместе с фоновой синхронизацией приложения, поэтому они могут задержаться на время, заданное режимом в **Настройки** › **Общие** › **Фоновая синхронизация**. См. [Как часто приложение синхронизируется](/ru/watchlist#interval).

Нажмите **Отложить** в уведомлении, чтобы этот фидер не беспокоил вас, пока снова не появится в сети. Для проблем фидера, который в сети, откладывание действует, пока они не исчезнут.

Без сервера приложение само проверяет airplanes.live и показывает «Обнаружены offline фидеры», когда фидер не виден в течение выбранного времени. Проверка выполняется каждые 60 минут.

## Поделиться фидером
{: #share }

**Создать QR-код** показывает QR-код с настройками фидера. Отсканируйте его через **Сканировать QR-код** в приложении на другом устройстве, чтобы добавить туда тот же фидер.
